# 규제 컴플라이언스 베이스 구축 계획

작성 기준: 2026-11-22(KST). 이 문서는 **구현 전 제안**이다. 1절만 관측한 사실이고 나머지는 계획이다.

## 1. 현재 확인 범위

| 항목 | 상태 | 근거 |
|---|---|---|
| 법령 원문을 조문 단위로 받는 공식 창구의 존재 | 확인 | 국가법령정보 공동활용 사이트 API 안내 목록(`open.law.go.kr/LSO/openApi/guideList.do`)을 2026-11-22에 읽음 |
| 안내 목록에 있는 조회 항목 | 확인 | 현행 법령(시행일·공포일 기준) 목록·본문·조항호 단위 본문, 자치법규 목록·본문·별표ㆍ서식, 행정규칙 목록·본문·별표ㆍ서식, 법령해석례 목록·본문, 조문별 변경 이력 |

| 제주도 조례가 어디까지 포함되는지 | 미확인 | 자치법규 항목이 있다는 것만 확인 |
| 원문의 재배포 조건 | 미확인 | 확인 전에는 원문을 Git에 넣지 않는다 |

## 2. 수집 대상 후보

아래는 **기억에 기반한 후보**이며 원문과 현행 여부를 확인하지 않았다. 0단계에서 법령명·소관·현행 여부를 확정하고, 확정된 것만 수집 대상 목록으로 옮긴다.

| 분류 | 후보 | 예상 문서 유형 |
|---|---|---|
| 보전·출입 | 제주특별법의 절대·상대·관리보전지역 | 법률·시행령·조례 |
| 보전·출입 | 곶자왈 보전 관련 조례 | 조례 |
| 보전·출입 | 오름 자연휴식년제 | 고시 |
| 총량·예약 | 한라산 탐방예약제 | 고시·공고 |
| 총량·예약 | 거문오름 사전예약 | 고시·공고 |
| 총량·예약 | 렌터카 총량제 | 법률 특례·조례 |
| 총량·예약 | 우도 차량 운행 제한 | 고시·공고 |
| 부담금·환경 | 환경보전분담금(논의 단계로 기억) | 연구용역·계획 |
| 부담금·환경 | 일회용컵 보증금제 | 법률·고시 |
| 생태관광 | 생태관광 육성·지원 조례 | 조례 |
| 생태관광 | 환경부 생태관광지역 지정 | 법률·고시 |
| 숙박 | 농어촌민박 기준, 미신고 숙박 단속 | 법률·조례 |

문서 유형에 따라 수집 경로가 다르다.

- **법률·시행령·조례·행정규칙**: 1절의 API(확인 후 사용).
- **도 고시·공고, 국립공원 공고**: 기관 홈페이지의 첨부 파일(HWP·PDF). 별도 파서가 필요하다.
- **행정계획·연구용역**: PDF. 규범이 아니므로 조문 저장소와 구분해 "계획·논의" 자료로 둔다.

## 3. 저장 구조: 두 층

### 3.1 원문 조문 저장소

문서를 임의 길이로 자르지 않고 **조·항·호 단위**로 저장한다. 검색과 인용의 단위가 조문이기 때문이다.

| 필드 | 뜻 |
|---|---|
| `provision_id` | 저장소 내부 조문 식별자 |
| `law_id`, `law_name`, `law_type` | 법령 식별자, 이름, 종류(법률·시행령·조례·규칙·고시·공고) |
| `article`, `paragraph`, `item` | 조·항·호 번호 |
| `text` | 원문 그대로. 요약하거나 고치지 않는다 |
| `effective_date`, `promulgation_date` | 시행일, 공포일 |
| `status` | 현행·개정 예정·폐지 |
| `source_url`, `retrieved_at`, `content_hash` | 출처, 수집 시각, 원문 해시 |

### 3.2 규제 카드

조문에서 규제의 내용을 구조화한 것이다. 기능 C의 적합성 판정은 이 카드로 한다.

| 필드 | 뜻 |
|---|---|
| `card_id` | 카드 식별자 |
| `target_activity` | 대상 행위(예: 차량 반입, 탐방, 숙박 영업) |
| `target_area` | 대상 지역. 조문에 적힌 표현 그대로 |
| `obligation_type` | 금지·허가·신고·예약·총량·부담금 |
| `numeric_criteria` | 수치 기준과 단위. 조문에 없으면 `null` |
| `penalty` | 벌칙·과태료. 조문에 없으면 `null` |
| `provision_ids` | 근거 조문 목록. 비어 있으면 카드로 인정하지 않는다 |
| `enforcement_status` | 시행·유예·논의·폐지 |
| `evidence_grade` | `verified`(사람이 원문과 대조), `extracted`(모델 추출, 미검수), `candidate`(원문 없음) |
| `reviewed_at` | 검수 시각 |

카드는 모델이 추출하고 사람이 검수한다. `verified`가 아닌 카드로는 "통과"나 "저촉"을 판정하지 않고 "확인 필요"로 답한다.

## 4. 파싱

- **API 응답**: 조·항·호 구조를 그대로 옮긴다. 별표는 별도 문서로 저장하고 본문 조문에서 참조한다.
- **HWP·PDF 첨부**: 텍스트로 변환한 뒤 조문 번호 패턴으로 나눈다. 표는 구조가 깨지기 쉬우므로 표가 있는 문서는 사람이 대조한다.
- **개정 추적**: 조문별 변경 이력을 받아 시행일 기준으로 버전을 남긴다. 답변은 질문 시점에 유효한 버전만 쓴다.
- 파서는 네트워크를 호출하지 않는다. 수집과 파싱을 분리해, 받은 원문 파일에서 같은 결과를 다시 만들 수 있게 한다.

## 5. 검색

- **키워드 검색**: 법령명과 조문 번호는 정확히 일치해야 하므로 반드시 둔다.
- **임베딩 검색**: 일상 표현의 질문("우도에 차 가져가도 되나")을 조문에 연결한다. 참고 저장소에서 비교한 `intfloat/multilingual-e5-large`를 출발점으로 삼고, 법령 문장에서의 성능은 따로 잰다.
- **필터**: 시행일, 법령 종류, 지역.
- 저장소는 참고 저장소가 후보로 둔 PostgreSQL + pgvector를 우선 검토한다. 초기에는 JSON 파일로 시작해도 된다.

## 6. 인용 검증

보고서의 모든 규범 서술은 `provision_id`를 가진다. 내보내기 전에 다음을 검사한다.

1. 인용한 `provision_id`가 저장소에 있다.
2. 인용문이 해당 조문의 원문과 일치한다.
3. 해당 조문이 보고서 기준일에 유효하다.
4. 수치와 벌칙이 규제 카드의 값과 일치한다.

실패한 서술은 제거하거나 "확인 필요"로 바꾼다. 실패를 정상 서술로 내보내지 않는다.

## 7. RAG로 알 수 없는 것

| 알고 싶은 것 | 왜 안 되는가 | 대안 |
|---|---|---|
| 특정 위치가 보전지역에 속하는지 | 구역은 지도 데이터로 정해진다 | 공간 데이터를 따로 연결 |
| 실제 집행 현황(단속 건수, 예약 마감률) | 조문에 없다 | 통계·보도자료를 별도 수집 |
| 조문의 해석이 갈리는 경우의 결론 | 유권해석의 영역이다 | 법령해석례를 근거로 제시하고 소관 부서 확인을 안내 |
| 수집 이후의 개정 | 저장소는 수집 시점의 사본이다 | 주기적 재수집과 기준일 표시 |

## 8. 완료 조건

- 시범 지역의 수집 대상 법령이 모두 조문 단위로 저장되고, 각 조문에 시행일과 출처가 있다.
- 시범 지역의 규제 카드가 모두 `verified`이거나, 아닌 카드가 목록으로 드러나 있다.
- 사람이 고른 점검 질문에서 인용 검증이 틀린 인용을 잡아낸다.
