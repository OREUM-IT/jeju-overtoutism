# 읽기 전용 도구와 답변 인용 검사

작성 기준: 2026-11-23(KST). [로드맵](03-roadmap-and-evaluation.md) 4단계의 결과다. 완료 조건은 "틀린 인용이 자동으로 차단됨"이다.

## 1. 만든 것

| 파일 | 내용 |
|---|---|
| [`scripts/tools.py`](../scripts/tools.py) | Agent가 부를 읽기 전용 도구 6개. 결과를 JSON으로 내놓는다 |
| [`scripts/verify_answer.py`](../scripts/verify_answer.py) | 답변·보고서의 서술마다 근거가 실제로 있는지 검사한다 |
| [`data/verify-samples.json`](../data/verify-samples.json) | 검사기가 잡아야 할 것과 통과시켜야 할 것의 견본 13개 |

둘 다 표준 라이브러리만 쓰고, 파일을 쓰지 않으며, 네트워크를 호출하지 않는다.

## 2. 읽기 전용 도구

[01 문서](01-product-and-scope.md) 4절의 도구 초안과 [10 문서](10-service-plan.md) 7절의 API 계약에 대응한다.

| 도구 | 하는 일 | 대응하는 계약 |
|---|---|---|
| `search_regulation_cards` | 질문으로 카드를 찾는다. 기간이 끝났는지(`period_ended`)를 함께 준다 | `GET /api/cards` |
| `get_card` | 카드 한 건 전체 | `GET /api/cards/{card_id}` |
| `search_provisions` | 조문 검색. "법령 이름 + 제○조"면 바로 찾는다 | `search_provisions` |
| `get_provision` | 조문 한 건의 원문, 시행일, 문서 이름 | `get_provision` |
| `search_notices` | 고시·공고 검색 | 없음(추가 제안) |
| `list_expiring` | 기간이 끝났거나 곧 끝나는 규제, "별도 고시일까지"인 규제 | 없음(추가 제안) |

판정 도구(`check_regulation_fit`)는 여기에 없다. 판정 규칙은 `web/lib/checks/`에 카드별로 있다.

```
python scripts/tools.py search_regulation_cards --query "우도에서 전동킥보드 빌려도 되나"
python scripts/tools.py get_provision --id "L01:제432조"
python scripts/tools.py list_expiring --date 2026-11-23 --days 90
```

`list_expiring`의 2026-11-23 결과:

| 상태 | 대상 | 종료일 |
|---|---|---|
| 끝남 | 우도면 내 일부자동차 운행제한 | 2026-07-31 |
| 90일 안에 끝남 | 자연휴식년제 - 도너리오름 | 2026-12-31 |
| 별도 고시일까지 | 한라산 탐방예약제, 낚시통제구역, 백약이오름, 오름 27곳의 출입·취사·야영 제한 | 없음 |

이 도구들은 아직 명령줄로만 부를 수 있다. MCP나 HTTP로 감싸는 일은 하지 않았다.

## 3. 답변 인용 검사

입력은 [10 문서](10-service-plan.md) 7절의 보고서 응답과 같은 모양이다. JSON 어디에 있든 `kind`, `text`, `basis`(또는 `source_refs`)를 가진 객체를 서술로 보고 검사한다.

| 검사 | 내용 | 어기면 |
|---|---|---|
| 근거 존재 | 사실 서술에는 인용문이 있는 근거나 수집 대상 ID가 하나 이상 있어야 한다 | 차단 |
| 인용 대상 | 카드, 수집 대상 ID, 조문 ID가 실제로 있어야 한다 | 차단 |
| 인용문 일치 | 카드 인용문은 그 카드에 적힌 인용문과, 조문 인용문은 그 조문의 글과 같아야 한다 | 차단 |
| 수치 | 서술의 숫자(두 자리 이상)는 인용한 카드·조문·수집 대상 항목에 있어야 한다. "제25조" 같은 조문 번호는 뺀다 | 차단 |
| 시행 상태 | 폐지됐거나 기간이 끝난 카드를 근거로 든 사실 서술 | 경고 |

사실이 아닌 서술(`unknown`, `measure`)은 차단하지 않고 경고만 한다. 기간이 정해진 카드는 기준일이 기간 안이면 경고하지 않는다(10 문서 4.2절 3번과 같은 규칙).

```
python scripts/verify_answer.py <답변.json> --date 2026-11-23
python scripts/verify_answer.py --self-check data/verify-samples.json
```

### 견본으로 점검한 결과

견본 13개가 모두 기대와 같았다.

| 견본 | 기대 | 결과 |
|---|---|---|
| 카드 인용문이 맞는 사실 서술 | 통과 | 통과 |
| 인용문을 고친 경우("16인승"을 "6인승 이하"로) | 차단 | 차단 |
| 근거에 없는 숫자(과태료 50만원) | 차단 | 차단 |
| 근거가 전혀 없는 사실 서술 | 차단 | 차단 |
| 없는 카드, 수집 대상 목록에 없는 ID | 차단 | 차단 |
| 조문에 없는 말을 조문 인용으로 적은 경우 | 차단 | 차단 |
| 기간이 끝난 카드, 폐지된 카드를 근거로 든 사실 서술 | 경고 | 경고 |
| 근거 없는 제안에 숫자가 있는 경우 | 경고 | 경고 |

견본은 작성자가 정한 것이고, 견본을 보며 검사기를 고쳤다. 검사기가 망가지지 않았는지 보는 점검이다.

### 웹 시안의 보고서를 검사한 결과

`web/lib/report.ts`가 만드는 지역 진단 보고서 3종을 그대로 받아 검사했다(기준일 2026-11-23).

| 보고서 | 서술 | 통과 | 차단 | 경고 |
|---|---|---|---|---|
| 정책 담당자용 | 17개 | 15개 | 2개 | 2개 |
| 사업자용 | 8개 | 6개 | 2개 | 1개 |
| 여행자용 | 8개 | 6개 | 2개 | 4개 |

- **규제에 관한 사실 서술은 모두 통과했다.** 인용문이 카드에 글자 그대로 있고, 과태료 10만원 같은 숫자도 근거에 있다.
- **경고는 모두 같은 이유다.** 우도 운행제한 카드의 기간이 2026-07-31에 끝났다. 웹은 이 경우 최종 판정을 "확인 필요"로 낮추므로 화면의 동작과 맞는다.
- **차단된 2개는 세 보고서에서 같다.** "규제 카드 9건 가운데 9건이 검수 전이다"와 "원문 수집일은 2026-11-23이다"다. 틀린 말이 아니라, 사실 서술로 표시되어 있는데 근거 항목이 비어 있어서다.

## 4. 계약에서 정해야 할 것

차단된 2개는 규제가 아니라 **자료의 상태**를 말하는 서술이다. 지금 계약에는 이런 서술을 나타낼 방법이 없다. 둘 중 하나로 정해야 한다.

| 안 | 내용 | 검사기 |
|---|---|---|
| 서술 종류 추가 | `kind`에 `meta`(자료 상태)를 더한다 | 이미 지원한다. `meta`는 인용을 검사하지 않는다 |
| 자료를 근거로 표시 | `source_refs`에 `cards`나 `udo-regulation-sources.csv` 같은 자료 이름을 적는다 | 이미 지원한다. 그 자료의 건수가 숫자의 근거가 된다 |

`web/`은 다른 작업에서 만들고 있어 이번에는 고치지 않았다. 어느 안으로 갈지 정한 뒤 `web/lib/report.ts`를 고치면 세 보고서가 차단 없이 통과한다.

## 5. 한계

- **통과는 "근거가 실제로 있다"는 뜻일 뿐이다.** 서술이 근거의 뜻을 바르게 옮겼는지는 보지 못한다. "16인승"을 인용해 놓고 "모든 전세버스가 가능하다"고 쓰면 통과한다.
- 숫자 검사는 글자만 본다. "십만원"처럼 한글로 쓴 수나 한 자리 숫자는 보지 않는다. 날짜는 연·월·일 숫자가 근거 어딘가에 있으면 통과한다.
- 카드 인용은 카드에 적힌 인용문과 맞춰 본다. 카드의 인용문이 원문에 있는지는 `scripts/check_card_quotes.py`가 따로 본다. 둘을 함께 돌려야 원문까지 이어진다.
- 조문 인용은 `.local/provisions`가 있어야 확인한다. 레포만 받은 환경에서는 건너뛰고 그렇다고 알린다.
- 도구의 검색은 [09 문서](09-search.md)의 한계를 그대로 가진다.

## 6. 다음에 할 일

1. 4절의 계약을 정하고 `web/lib/report.ts`를 맞춘다.
2. 검사기를 웹의 보고서 API에 연결한다. 응답을 내보내기 전에 검사하고, 차단된 서술을 빼거나 "확인 필요"로 바꾼다.
3. 도구를 MCP 또는 HTTP로 감싸 Agent가 부를 수 있게 한다.
4. `list_expiring`을 주기적으로 돌려 후속 고시를 확인할 목록을 만든다.
5. 뜻이 맞는지까지 보는 검사를 검토한다. 모델로 판정하게 되면 그 판정의 근거도 남겨야 한다.
