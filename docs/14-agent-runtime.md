# 규제 Agent 실행

작성 기준: 2026-11-24(KST). [읽기 전용 도구와 인용 검사](11-agent-tools-and-citation-check.md)를 묶어 질문에 답하는 Agent로 만들고, 명령줄·HTTP·MCP 세 가지로 부를 수 있게 했다.

## 1. 지금 되는 것과 안 되는 것

| | 상태 |
|---|---|
| 모델 없이 답하기(카드에서 항목을 골라 인용문과 함께 내놓음) | 된다. 이 컴퓨터에서 실행해 확인했다 |
| HTTP 서버(`/v1/ask`), 시험 화면 | 된다. 실제로 띄워 `curl`과 브라우저로 확인했다 |
| MCP 서버(stdio, HTTP) | 된다. 공식 MCP SDK 클라이언트(1.32.1)로 붙어 도구 7개를 불렀다 |
| 모델로 답하기, `brief` 방식(자료는 코드가 찾고 모델은 한 번만 불러 문장을 씀) | 된다. 이 컴퓨터의 Ollama `qwen3:4b`(CPU만)로 질문 21개를 돌려 쟀다(4절) |
| 모델로 답하기, `tools` 방식(모델이 도구를 불러 스스로 찾음) | 가짜 모델 주소로만 시험했다. `qwen3:4b`는 늘 '생각'을 먼저 길게 써서 이 컴퓨터에서는 호출 한 번이 10분을 넘겼다 |
| 배포(AWS 등), 오름잇 화면에 붙이기 | 하지 않았다 |
| 판정("저촉", "허가 대상") | 하지 않는다. 판정 규칙은 오름잇 앱(`OREUM-IT/jeju-tour`)에 있다. 이 Agent는 관련 규제와 근거를 찾아 준다 |

## 2. 구조

참고 저장소 [jeju-tour-data-analysis](https://github.com/OREUM-IT/jeju-tour-data-analysis)의 역할 나눔을 따랐다. 그쪽은 Node와 Langflow를 쓰고, 여기는 Python 표준 라이브러리만 쓴다(설치할 것이 없다).

| 참고 저장소 | 이 저장소 | 하는 일 |
|---|---|---|
| `services/jeju-mcp` | [`scripts/mcp_server.py`](../scripts/mcp_server.py) | 읽기 전용 도구를 MCP로 내놓음 |
| `services/langflow`의 Agent 흐름 | [`scripts/agent.py`](../scripts/agent.py) | 찾기 → 답 만들기 → 인용 검사 |
| `services/agent-gateway` | [`scripts/agent_server.py`](../scripts/agent_server.py) | 인증, 크기·동시 처리 제한, HTTP 주소 |

질문 하나의 흐름:

1. **찾기.** 질문으로 규제 카드를 찾는다. 질문이 부른 곳(우도, 한라산 등)이 대상 지역이나 제목에 있는 카드를 앞에 둔다.
2. **답 만들기.** 두 가지 가운데 하나.
   - `grounded`(모델 없음): 카드에서 질문과 가까운 항목을 골라 "요약 + 인용문"으로 늘어놓는다. 기간이 끝났거나 효력을 확인하지 못한 카드면 그 말을 먼저 한다. 카드의 "아직 확인하지 못한 것"도 싣는다.
   - `model`, `brief` 방식(기본): 코드가 카드를 찾아 항목마다 번호(E1, E2 …)를 붙여 모델에 준다. 모델은 한 번의 호출로 문장을 쓰고 서술마다 번호만 단다. 인용문은 코드가 번호로 찾아 글자 그대로 붙인다. 답의 모양은 JSON 스키마(`response_format`)로 묶는다. 이렇게 하면 '생각'을 먼저 쓰는 모델도 바로 답을 쓴다. 카드의 기간 종료·검수 전 같은 상태 문구는 모델에 맡기지 않고 코드가 붙인다(모델이 실제로 인용한 카드에만).
   - `model`, `tools` 방식: 모델에 도구 6개를 주고 스스로 찾게 한다. 모델이 인용문을 글자 그대로 옮겨야 한다. 호출은 8번까지이고 마지막 호출은 도구 없이 답만 받는다. 도구 호출을 잘하는 큰 모델에서만 쓴다.
3. **검사.** 서술마다 [`verify_answer.check_statement`](../scripts/verify_answer.py)로 인용문이 카드나 조문에 실제로 있는지, 서술의 숫자가 근거에 있는지 본다. 통과하지 못한 사실 서술은 답에서 빼고 `verification.blocked`에 남긴다. "규제가 없다"처럼 없음을 말하는 사실 서술은 인용이 맞아도 뺀다. 모델이 쓴 사실 서술은 둘을 더 본다.
   - **말 겹침.** 서술의 말(두 글자 단위)이 인용문과 그 항목의 요약에 30% 넘게 들어 있어야 한다. 맞는 인용을 달고 다른 말을 하는 문장을 뺀다.
   - **조건.** 근거에 "위반하여", "허가 없이", "밖에서", "제외" 같은 조건이 있는데 서술에 조건이 하나도 없으면 뺀다. 실제로 `qwen3:4b`가 "포획·채취 기준을 위반하여 채취해서는 안 된다"를 근거로 "해루질은 비어업인에게 금지된 활동"이라고 썼다. 인용 검사는 이것을 통과시켰다.
   - 카드 요약 364개를 모델 문장처럼 넣어 보면 18개(5%)가 이 두 검사에 걸린다. 맞는 말을 조금 지나치게 빼는 쪽으로 맞췄다.
4. **되돌아가기.** 모델의 답이 JSON이 아니거나, 모델 주소에 닿지 못하거나, 검사를 통과한 사실 서술이 없으면 `grounded` 답을 내고 `fallback_reason`에 까닭을 적는다. 관련 카드가 없으면 모델을 부르지 않는다.

답의 모양(`ask()`가 돌려주는 값, `/v1/ask`의 응답):

```json
{
  "question": "우도에 렌터카 가져가도 되나", "as_of": "2026-11-24",
  "mode": "grounded", "model": null, "fallback_reason": "",
  "statements": [
    {"kind": "unknown", "text": "「우도면 내 일부자동차 운행(통행)제한 명령」 카드 주의: 기간이 2026-07-31에 끝남. …", "basis": [{"card_id": "udo-vehicle-restriction-2026-715"}], "warnings": []},
    {"kind": "fact", "text": "[제한 대상 R1] 전세버스 운송사업용 자동차와 자동차 대여사업용 자동차",
     "basis": [{"card_id": "udo-vehicle-restriction-2026-715", "item_id": "R1", "quote": "전세버스 운송사업용 자동차 및 …", "locator": "4 첫째 항목"}],
     "warnings": ["근거 카드 주의(udo-vehicle-restriction-2026-715): 기간이 2026-07-31에 끝남"]}
  ],
  "cards": [{"card_id": "udo-vehicle-restriction-2026-715", "evidence_grade": "extracted"}],
  "verification": {"kept": 16, "blocked": [], "warnings": 6, "provisions_checked": true},
  "trace": [], "disclaimer": "법률 자문이 아니다. …"
}
```

`kind`는 `fact`(인용으로 확인한 사실), `unknown`(확인하지 못한 것), `measure`(제안), `meta`(자료의 상태)다.

## 3. 돌리는 법

저장소 폴더에서. Python 3.10 이상이면 되고 설치할 패키지는 없다.

```
python scripts/agent.py "우도에 렌터카 가져가도 되나"
python scripts/agent.py "새별오름에서 캠핑해도 되나" --date 2026-11-24 --json
```

시험 화면(이 컴퓨터에서만):

```
python scripts/agent_server.py --no-auth
```

브라우저로 `http://127.0.0.1:8790`을 연다. `--no-auth`는 127.0.0.1로 띄울 때만 받는다.

HTTP 서버(다른 프로그램이 부를 때): `.env`에 `AGENT_AUTH_KEY`(32자 이상)를 넣고

```
python scripts/agent_server.py --host 127.0.0.1 --port 8790
```

| 주소 | 인증 | 내용 |
|---|---|---|
| `GET /healthz` | 없음 | 살아 있는지만 |
| `GET /readyz` | 필요 | 카드 수, 조문 저장소 유무, 모델 설정 여부 |
| `POST /v1/ask` | 필요 | `{"question": "...", "date": "YYYY-MM-DD", "mode": "auto"}` → 2절의 JSON |
| `POST /mcp` | 필요 | MCP(Streamable HTTP, 상태 없음) |

인증은 `Authorization: Bearer <AGENT_AUTH_KEY>`다. 본문은 8KB까지, 질문은 500자까지, 동시에 2건까지(넘으면 429)다.

MCP(Claude Desktop, Claude Code, Langflow 등에서 도구로 쓸 때):

```json
{"command": "python", "args": ["scripts/mcp_server.py"], "cwd": "<이 저장소의 폴더>"}
```

도구는 `ask_regulation`(검사를 거친 답)과 [11 문서](11-agent-tools-and-citation-check.md)의 찾기 도구 6개(`get_card` 대신 인용할 항목만 주는 `get_card_items`)다. 모두 읽기 전용이다.

시험:

```
python scripts/test_agent.py
```

38개. 모델 경로는 이 파일이 띄우는 가짜 모델 주소로 시험한다(두 방식, 지어낸 인용·숫자·번호 빼기, 뜻을 바꾼 문장 빼기, JSON이 아닌 답, 끝없이 도구만 부르는 모델, 닿지 않는 주소, 질문 안의 지시).

질문 묶음([`data/search-checks.json`](../data/search-checks.json)의 21개)으로 실제 모델을 잴 때:

```
python scripts/eval_agent.py --show
```

## 4. 모델을 붙이려면

`.env`에 주소와 이름을 넣으면 `mode: auto`가 모델을 쓴다. 키와 주소는 `.env`에만 두고 Git에 올리지 않는다.

```
AGENT_MODEL_BASE_URL=http://127.0.0.1:11434/v1
AGENT_MODEL=qwen3:4b
AGENT_MODEL_TIMEOUT=300
```

- **Ollama(내 컴퓨터).** 참고 저장소의 로컬 기본 모델이 `qwen3:4b`다. `ollama pull qwen3:4b`로 받는다(약 2.5GB). 지금 이 이름으로 받으면 늘 '생각'을 먼저 쓰는 판(Qwen3-4B-Thinking-2507, 문맥 262,144)이 온다. `think: false`나 `/no_think`로도 끌 수 없었고, `brief` 방식의 JSON 스키마로 묶어야 바로 답했다.
- **이미 쓰는 주소.** `/chat/completions`와 `response_format`(JSON 스키마)을 지원하는 OpenAI 호환 주소면 `brief` 방식이 된다. `tools` 방식은 도구 호출(`tools`, `tool_calls`)도 필요하다. 참고 저장소의 Vertex AI 설정을 그대로 쓰려면 OpenAI 호환 게이트웨이가 앞에 있어야 한다. 없으면 `chat()` 함수 하나를 그 API에 맞게 바꾼다.

### 실측(2026-11-25, Ollama 0.40.17, `qwen3:4b` Q4_K_M, Intel Core Ultra 9 185H, 그래픽 카드 없이 CPU만)

`python scripts/eval_agent.py --show`, 질문 21개, `brief` 방식.

| | 값 |
|---|---|
| 모델이 답한 질문 | 20 / 21. 나머지 1개("제주특별법 제432조")는 관련 카드가 없어 모델을 부르지 않았다 |
| 남은 사실 서술 | 55개(질문당 1~6개) |
| 검사에서 뺀 서술 | 3개. 모두 '조건 빠짐' 검사. 1개는 카드 요약과 같은 말이었다(지나친 차단) |
| 기대한 카드가 답에 실림 | 13 / 14 |
| 걸린 시간 | 질문당 46~183초, 평균 약 71초(잠자기 상태로 멈췄던 1건은 뺐다) |

같은 묶음을 말 겹침·조건 검사 전에 돌렸을 때 남은 사실 서술 53개 가운데 1개("해루질은 비어업인에게 금지된 활동입니다")가 근거의 조건을 빼고 뜻을 바꾼 문장이었다. 그 문장을 시험에 넣었다.

읽어 보면 모델의 답은 대체로 근거의 말을 그대로 옮긴다. 대신 질문에 바로 답하지 않고 관련 조항을 나열하는 경우가 많고("상대보전지역에서 숙박시설을 지을 수 있다면, 해당 숙박시설이 …"처럼 어색한 문장도 있다), 질문당 1분 남짓 걸린다. 지금 이 컴퓨터에서는 **모델 없는 답(0.01초)이 기본으로 낫고**, 모델은 문장을 다듬는 선택지다. 그래픽 카드가 있는 서버나 큰 모델에서 다시 재 볼 만하다.

## 5. 지키는 것

- 도구는 읽기만 한다. 파일을 쓰지 않고, 모델 주소 말고는 네트워크를 부르지 않는다.
- 질문은 자료로 다룬다. 질문 안에 "규칙을 무시하라"가 있어도 근거 없는 사실 서술은 검사에서 빠진다.
- 카드를 찾지 못하면 "찾지 못했다"고만 답한다. 카드가 없다는 것이 규제가 없다는 뜻이 아니라고 함께 적는다.
- 서버는 인증 키 없이 시작하지 않는다. 질문은 기록에 남기지 않고(주소와 상태 코드만), 내부 오류의 내용은 밖으로 내보내지 않는다.
- 다른 사이트의 화면이 이 서버를 부르지 못하게 `Origin`을 본다. 브라우저에서 직접 부르게 하려면 `AGENT_ALLOWED_ORIGIN`에 그 주소 하나를 적는다.
- 밖에 내놓을 때는 앞에 HTTPS와 접근 제어를 둔다. 이 서버는 HTTP만 말한다.

## 6. 한계

- **모델 없는 답은 판단하지 않는다.** 관련 카드의 항목을 늘어놓을 뿐이다. "곶자왈에서 드론 날려도 되나"를 물으면 곶자왈 카드의 항목이 나오지만 드론에 관한 항목은 없다(카드에 없다). 질문의 행위가 카드에 없다는 것을 따로 말해 주지 않는다.
- **카드 14건이 전부다.** [커버리지](../data/coverage.json)에서 `text_only`·`missing`인 것은 답하지 못한다.
- **카드가 모두 검수 전이다.** 답마다 "사람의 검수 전"이라는 자료 상태 서술이 붙는다.
- 항목 고르기는 낱말 겹침이다. 질문의 말과 카드의 말이 다르면(별칭 사전에 없으면) 덜 맞는 항목이 나온다.
- 조문 저장소(`.local/provisions`)가 없는 곳에서는 조문을 근거로 든 서술을 확인하지 못하고 경고만 붙인다. 카드 인용은 저장소 없이도 검사한다.
- 대화의 앞뒤를 기억하지 않는다. 질문 하나에 답 하나다.
- **모델 문장의 검사는 기계적이다.** 인용, 숫자, 말 겹침, 조건 낱말을 볼 뿐 뜻을 이해하지 않는다. 조건 낱말을 남긴 채 뜻을 바꾼 문장은 통과할 수 있다. 그래서 답마다 원문 인용을 함께 보여 준다. 반대로 맞는 문장도 5% 안팎 빠진다.

## 7. 다음에 정할 것

1. 모델을 무엇으로 할지. 이 컴퓨터의 `qwen3:4b`(CPU)는 돌지만 질문당 1분 남짓이다. 그래픽 카드가 있는 서버, 참고 저장소의 Vertex AI, 그 밖의 주소 가운데 고르면 `scripts/eval_agent.py`로 같은 21개 질문을 다시 잰다.
2. 어디에 띄울지. 참고 저장소처럼 AWS에 올리고 Cloudflare Access 뒤에 둘지, 오름잇 서버(Vercel 함수)가 이 저장소의 자료 사본으로 같은 일을 할지.
3. 오름잇의 「규제 확인」 화면에 질문 칸을 붙일지. 붙인다면 그 화면의 판정 규칙과 이 Agent의 답을 어떻게 함께 보여 줄지.
