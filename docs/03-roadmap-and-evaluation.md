# 단계별 로드맵과 평가

작성 기준: 2026-11-22(KST). 이 문서는 **구현 전 제안**이다. 일정은 정하지 않았다.

## 1. 진행 원칙

- 규제 컴플라이언스 베이스를 먼저 만든다. 보고서는 그 위에 올린다.
- 세 기능(규제 조회, 대응 방향, 아이템 기획)을 **시범 지역 한 곳**에서 얕게 함께 만든 뒤 넓힌다.
- 각 단계는 완료 조건을 만족해야 다음으로 넘어간다.

## 2. 시범 지역

**우도를 제안한다.** 차량 규제, 혼잡, 생태 자원이 한 지역에 모여 있어 세 기능을 모두 시험하기 좋다고 판단했다. 이 판단은 원문 확인 전의 것이며, 0단계에서 우도에 적용되는 규제가 실제로 수집 가능한지 본 뒤 확정한다.

## 3. 단계

| 단계 | 내용 | 완료 조건 |
|---|---|---|
| 0 | 수집 대상 법령·조례·고시 목록 확정, API 이용 신청 | 시범 지역의 대상 목록과 각 항목의 수집 경로 |
| 1 | 법령·조례 수집기와 조문 파서 | 조문 단위 원문과 시행일이 저장됨. 같은 입력에서 같은 결과가 나옴 |
| 2 | 고시·공고(HWP·PDF) 파싱 | 운영 기준이 출처와 함께 저장됨 |
| 3 | 검색과 규제 카드 추출·검수 | 점검 질문에 근거 조문이 검색되고 카드가 검수됨 |
| 4 | 읽기 전용 도구와 인용 검증 | 틀린 인용이 자동으로 차단됨 |
| 5 | 보고서 생성 | 독자 유형별 시범 보고서 3종 |
| 6 | 지역·법령 확대, 정식 평가셋, 부하 지표 연결 | 5단계 결과를 보고 결정 |
| 7 | 배포와 기존 서비스 연결 | 6단계 이후 결정 |

0단계의 API 이용 신청은 계정 소유자가 직접 한다.

## 4. 평가

### 자동으로 판정하는 것

| 지표 | 판정 |
|---|---|
| 인용 존재 | 인용한 조문 ID가 저장소에 있는가 |
| 인용 일치 | 인용문이 원문과 같은가 |
| 시행 상태 | 폐지·논의 중인 제도를 시행 중으로 서술하지 않았는가 |
| 근거 없는 수치 | 저장소에 없는 수치가 보고서에 있는가 |
| 미확인 고지 | `verified`가 아닌 카드에 근거한 판정을 "확인 필요"로 표시했는가 |

정답은 규칙으로만 계산한다. 모델이 정답을 쓰거나 고치지 않는다.

### 사람이 판정하는 것

기능 B와 C의 결과에는 하나의 정답이 없다. 채점 기준표로 사람이 검수한다.

- 독자에게 맞는가(정책 담당자, 사업자, 여행자)
- 제시한 수단·기획이 인용한 규제와 모순되지 않는가
- 실행에 필요한 확인 사항이 빠지지 않았는가
- 근거 있는 서술과 제안이 구분되어 있는가

초기에는 소규모 점검 질문으로 시작하고, 정식 평가셋은 6단계에서 만든다.

## 5. 반드시 포함할 실패 시나리오

- 폐지되었거나 논의만 된 제도에 대한 질문
- 저장소에 없는 지역·행위에 대한 질문(근거 없음으로 답해야 한다)
- 개정 전후로 내용이 다른 조문에 대한 질문
- 수집한 문서 안에 들어 있는 지시문(문서 내용은 명령이 아니라 데이터로 취급한다)
- 위치가 보전지역인지 묻는 질문(공간 데이터 없이는 확인 필요로 답해야 한다)

## 6. 열린 결정

| 항목 | 현재 기본값 | 정할 시점 |
|---|---|---|
| 시범 지역 | 우도(제안) | 0단계 |
